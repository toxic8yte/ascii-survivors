# Пакетная отрисовка ASCII

Поле Godot-версии использует `GlyphBatch`: шрифт Godot один раз формирует расположение каждой уникальной строки, растры глифов копируются в RGBA-атлас 1024×1024. Фиксированные страницы не зависят от последующего расширения внутреннего атласа шрифта. Кириллица и fallback-шрифты проходят через тот же TextServer, что и обычный текст.

Один экземпляр MultiMesh — один видимый символ: трансформация, цвет/прозрачность и прямоугольник UV. Буферы растут по мере необходимости, затем переиспользуются. Максимум 4096 символов на пакет; при смене страницы текстуры или переходе к обычному тексту пакет завершается. Порядок символов и слоёв сохраняется. Отсечение за границами поля выполняется на CPU **до** добавления символов; невидимые экземпляры в MultiMesh не передаются. Меню и подписи HUD остаются обычным текстом. Координаты глифов привязаны к пикселям, чтобы избежать размытия ASCII.

Это изменение рендера. Частота симуляции, количество/поведение врагов и механика оружия не менялись. SIMD, SoA, распределение AI по шагам и объединение зон урона в этой работе не внедрялись. Старый текстовый путь сохранён для сравнительных проверок, но не добавлен в игровое меню.

## Измерения

Windows Release, Godot 4.7.2 .NET, OpenGL Compatibility, i5-10400F / RTX 3060, окно 1920×1080, VSync отключён. Звуковая логика включена, вывод звука в тесте заглушён. Смешанная толпа из 6000 врагов, включая элиту, весь арсенал и пассивки максимального ранга. Враги имеют тестовое высокое здоровье; герой неподвижен и неуязвим.

Оба режима запускаются **одной и той же сборкой**, seed 781. Для неподвижного кадра выполняются ровно 300 шагов симуляции, затем 60 кадров прогрева и 240 измерений. В активном тесте также выполняются 300 шагов, прогревается рендер на паузе, затем измеряются следующие 15 секунд симуляции. В обоих запусках они заняли около 15 секунд реального времени.

| Измерение | Текст | Атлас |
| --- | ---: | ---: |
| Неподвижный кадр, среднее | 7,17 мс | 2,55 мс |
| Подготовка этого кадра на CPU | 5,68 мс | 1,72 мс |
| Активный бой, среднее | 11,57 мс | 4,20 мс |
| Активный бой, p95 | 15,38 мс | 9,62 мс |
| Средняя частота в активном тесте | ≈86 FPS | ≈238 FPS |

В неподвижном кадре одинаковы 4382 видимых врага / 3233 оттиска; новый путь выводит 12 717 глифов четырьмя пакетами. Все 6000 врагов сохраняются в симуляции.

**Это не стабильные 200 FPS:** p95 выше бюджета 5 мс, а тест короткий и синтетический. В секундных CSV нового запуска расталкивание занимает около 4,2 мс на шаг, весь шаг — около 7 мс; это следующий кандидат для оптимизации. Отдельные тяжёлые шаги при 60 Гц всё ещё создают длинные кадры. Получасовой прогон, другие GPU и высокий DPI не проверены.

Полные отчёты: [текст](benchmarks/godot-atlas-before.json), [атлас](benchmarks/godot-atlas-after.json). Это новые сопоставимые тесты; старые отчёты с фиксированным количеством кадров имели разные временные окна симуляции.

## Воспроизведение

В каталоге распакованной Windows-сборки, последовательно:

```powershell
./ASCII-Survivors.console.exe -- --render-benchmark=G:/anamation_JS/output/render-text --legacy-renderer
./ASCII-Survivors.console.exe -- --render-benchmark=G:/anamation_JS/output/render-atlas
```

Пути после `=` задают отдельные тестовые профили. Каждый запуск сохраняет `render.json`, `frozen-crowd.png`, `live-crowd.png` и локальную телеметрию. Не запускать сравнения одновременно. CSV дополнен полями `batched_glyphs` и `glyph_packets`: значения последнего подготовленного кадра секундного окна, а не счётчик GPU draw calls всего приложения. Эти же значения видны в «Движок».

## Проверки

3447 проверок симуляции/сохранений/телеметрии, включая 64 эталона оружия из JS. UI smoke проверяет семь размеров окна и fullscreen, бой с боссом, оружие, звук и меню. Дополнительно сравниваются кадры старого/нового рендера при обычном и малом окне: ASCII, кириллица, размеры шрифта 11/13/16/32 и полупрозрачность. Сравнение допускает небольшую разницу растеризации; отрицательный контроль с намеренно перевёрнутыми UV обязан провалить порог сходства.

При проверке завершения обнаружены оставшиеся аудиопотоки: `AudioController` теперь явно останавливает проигрыватели и очищает их `Stream` при выходе из дерева. Повторный Release smoke с `--verbose` завершился без предупреждений ObjectDB об утечках. В изолированной среде тестирования остаются сообщения о недоступном системном хранилище сертификатов и записи shader cache; ошибок нового рендера не зарегистрировано.

Основа реализации: [Godot MultiMesh](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html), [CanvasItem shaders / INSTANCE_CUSTOM](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html).
