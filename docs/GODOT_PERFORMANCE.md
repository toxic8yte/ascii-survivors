# Godot: плотные толпы, 2026-11-03

Проверено в Windows Release, Godot 4.7.2 .NET, Intel Core i5-10400F, NVIDIA RTX 3060, OpenGL Compatibility. Замеры одной машины, не требования к оборудованию и не гарантия FPS на других ПК.

## Причина и исправления

В расталкивании врагов лимит восьми соседей не прерывал перебор: после исчерпания бюджета цикл продолжал обходить плотную пространственную ячейку. Поэтому работа приближалась к квадрату количества врагов. Теперь проверяется максимум 32 кандидата и разрешается максимум восемь пересечений на врага за шаг; выборка в ячейке меняется между шагами. Пространственная сетка переиспользует списки, а проверка попаданий не копирует массивы соседей для каждого снаряда.

ASCII-рендер кэширует разобранные строки, ширину текста и canvas RID. При числе врагов больше 2000 обычные враги рисуются компактным символом: одинаковые тип и состояние в одной экранной ячейке 16×16 дают один отпечаток. Боссы, элиты, тренировочные манекены, подготовка рывков и сами рывки сохраняют полный вид. Все враги остаются в симуляции: здоровье, движение, контактный урон и попадания считаются отдельно. В окне «Движок» отдельно показаны количество врагов, видимых врагов и ASCII-оттисков.

## Расчёт симуляции

Одинаковая фиксированная сцена до/после: seed 781, `brute`, 100 миллионов HP (чтобы не убивать нагрузку), начальное время 15:00, песочница без новых волн и столкновений с ландшафтом. Плотная группа занимает радиусы 60–160, свободная — 140–940. Три шага прогрева и 12 измеряемых шагов по 1/60 секунды. CPU-замер использует стартовый набор, не полный арсенал. Включает AI, расталкивание, оружие и остальные действия шага; не включает отрисовку.

| Врагов | Размещение | До, мс/шаг | После, мс/шаг |
| ---: | --- | ---: | ---: |
| 1000 | Свободное | 2,69 | 2,26 |
| 5000 | Свободное | 12,60 | 5,02 |
| 10000 | Свободное | 33,14 | 10,09 |
| 1000 | Плотное | 3,39 | 1,14 |
| 5000 | Плотное | 90,52 | 4,60 |
| 10000 | Плотное | 348,09 | 10,74 |

В плотной группе из 5000 расталкивание вместе с перестроением сетки: 88,55 → 3,52 мс. Выделение управляемой памяти за шаг: 741,4 → 3,5 КиБ. Это сравнение времени вычислений, а не замер FPS. Короткие CPU-выборки чувствительны к JIT и фоновой нагрузке, особенно первый случай с 1000 врагов.

## Отрисовка

Статичная симуляция, 1920×1080, VSync выключен, 12 кадров прогрева и 48 измеряемых кадров. Полное время кадра и CPU-отправка команд рисования — разные величины. При плотных 5000: 38,38 → 1,41 мс/кадр, CPU в `_Draw`: 30,01 → 0,70 мс; при плотных 10000: 68,10 → 2,33 мс/кадр. Для плотных 5000 рисуется 305 отпечатков вместо 5000 перекрывающихся портретов. Ускорение плотного рендера включает уменьшение количества перекрывающихся отпечатков, а не только кэширование.

Живой тест: 5000 неубиваемых `brute`, все 33 оружия и пассивки максимального уровня, неуязвимый неподвижный герой, 100 кадров прогрева и 1800 измеряемых кадров. Оружие и симуляция работают: в среднем **14,71 мс/кадр**, p95 **17,23 мс**, всего прошло 27,93 секунды симуляции. Все 5000 врагов сохранились. Это искусственная плотная нагрузка; она не заменяет получасовой забег со смешанными врагами, боссами, добычей и перемещением по карте.

Исходные замеры: [CPU до](benchmarks/godot-cpu-before.json), [CPU после](benchmarks/godot-cpu-after.json), [рендер до](benchmarks/godot-render-before.json), [рендер после и живой бой](benchmarks/godot-render-after.json).

## Повторить

Из каталога экспортированной Windows-сборки:

```powershell
.\ASCII-Survivors.console.exe --headless -- --benchmark=C:/Temp/ascii-cpu.json
.\ASCII-Survivors.console.exe -- --render-benchmark=C:/Temp/ascii-render
```

Пути должны быть абсолютными. Первый режим сохраняет JSON без создания интерфейса; второй — JSON и снимок `live-5000.png`. Сохранения тестов изолированы от игрового профиля. Для сравнения запускайте CPU и рендер последовательно, без других нагрузочных тестов.

Проверка `-- --verify` также проверяет ограничение количества кандидатов, разделение совпадающих позиций и сохранение всех врагов при переиспользовании сетки. Остаются для проверки: получасовой обычный бой, другие ПК и патологические сцены с тысячами элит/телеграфов, которые специально не объединяются при отрисовке.
